🔐 Master Policy 엔진 설계 — Agent 계획, ZEZ 실행(Zero Exposure Zone)

Agent LLM은 원문 데이터값을 보지 않고, 컬럼 정보와 레시피·스킬 설명서를 바탕으로 암호화·범주화·패스스루 처리계획을 생성한다.
ZEZ(Zero Exposure Zone)는 OCR 추출 데이터, 사내 조회 데이터, 사내 정책 데이터의 3개 데이터셋을 만들고, Agent가 생성한 처리계획에 따라 실제 원문값을 암호화·범주화·패스스루·차단 처리한다.
암호화 태그는 의미 해석용이 아니라 3개 데이터셋 간 동일성 비교용이며, Agent LLM에는 원문, 복호화 키, 원문-암호문 매핑 테이블이 전달되지 않는다.

화면의 원문 예시는 설명을 위한 ZEZ 내부 예시입니다. 실제 Agent LLM은 컬럼명·데이터 타입·출처·업무 목적·레시피 태그 계약과 Master Policy 데이터만 수신합니다.
Master Policy 처리 파이프라인
사람이 데이터값마다 지정하지 않고, 레시피 태그 계약과 컬럼 메타데이터를 기반으로 Agent가 처리계획을 만들고 ZEZ가 실제 처리한다.

사람은 데이터값을 하나씩 지정하지 않고 레시피·스킬 설명서에 태그 처리 원칙을 정의한다.
Agent LLM은 컬럼 메타데이터와 태그 계약으로 처리계획을 만들며, ZEZ는 그 계획에 따라 실제 데이터값을 변환한다.
선택적 sLM은 원문값이 아니라 태깅 계획·컬럼 메타데이터·Master Policy만 검증하여 누락·충돌·오분류 가능성을 잡는다.

🧩 Master Policy Engine 스킬이 제공하는 처리 기준

암호화 태그

민감정보이면서 동일성 비교가 필요한 값. 예: 주민번호, 신청자명, 진단명, 진단군, 병원명.

패스스루

계산 또는 기간 판단에 필요한 저민감 값. 예: 신청금액, 진료일, 기존신청금액, 정책버전.

범주화 태그

회사 제도 판단에 필요한 상태값·검증결과. 예: 수진자관계, 기관검증상태, 지원조건, 중복기준.

차단

Agent 판단에 불필요하거나 고위험 원문. 예: 주민번호 원문, 원문 진단명, 원문 병원명.

의료비 Master Policy 라이브 데모
버튼을 누르면 ZEZ가 3개 데이터셋을 만들고, Agent LLM이 컬럼 기반 처리계획을 생성한 뒤, ZEZ가 Master Policy을 생성하는 흐름을 확인할 수 있습니다.

Agent LLM 입력 원칙
처리계획 수립 단계에서 Agent LLM은 원문값이 아니라 컬럼명, 데이터 타입, 데이터 출처, 업무 목적, 비교 필요성, 계산 필요성, 상태값 여부, 레시피 태그 계약만 본다. 실제 원문값은 ZEZ 내부에 남고, ZEZ가 계획대로 Master Policy 처리한다.
